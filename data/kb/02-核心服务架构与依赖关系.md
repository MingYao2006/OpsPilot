# 核心服务架构与依赖关系

## 服务清单

| 服务名 | 职责 | 负责人 | 等级 |
|---|---|---|---|
| pay-gateway | 支付网关，对外收单与渠道路由 | 支付组 | P1 |
| order-service | 订单中心，订单创建与状态机 | 交易组 | P1 |
| user-center | 用户中心，账号与鉴权 | 用户组 | P2 |
| notify-service | 消息通知，短信与推送 | 消息组 | P3 |
| risk-engine | 风控引擎，实时规则校验 | 风控组 | P2 |

## 依赖关系

调用链主路径：

    pay-gateway → order-service → risk-engine
    pay-gateway → user-center
    order-service → notify-service

关键约束：

- **pay-gateway 强依赖 order-service 与 risk-engine**，任一不可用则支付成功率降为 0
- order-service 对 notify-service 采用**异步削峰**，notify-service 故障**不会**阻塞下单
- risk-engine 超时阈值 200ms，超时按「放行但标记」处理，不阻断主链路

## 数据库与中间件归属

| 组件 | 归属 | 说明 |
|---|---|---|
| pay_db | pay-gateway | PostgreSQL 15，一主两从 |
| order_db | order-service | PostgreSQL 15，一主一从 |
| Redis 集群 | 公共 | 三主三从，用于缓存与分布式锁 |
| Kafka | 公共 | 用于 notify-service 削峰 |

## 排查时的定位建议

遇到告警先确认服务等级与依赖方向，避免在 P3 服务上投入 P1 的处置资源。
