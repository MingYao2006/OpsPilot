# 数据库主从与慢查询排查

## 慢查询判定

- 阈值：单条 SQL 执行时间 **超过 1 秒**即记录到慢查询日志
- 告警：**连续 3 分钟**内慢查询数量超过 **50 条/分钟**触发告警
- 统计类查询一律走从库，主库只承载点查与短事务

## 排查步骤

1. 登录对应实例，查看当前长时间运行的会话：

       SELECT pid, now() - query_start AS duration, state, left(query, 120)
       FROM pg_stat_activity
       WHERE state <> 'idle' AND now() - query_start > interval '1 second'
       ORDER BY duration DESC;

2. 若发现明显的全表扫描（缺索引、无 LIMIT 的大表查询），先与发起方确认后 kill：

       SELECT pg_cancel_backend(<pid>);   -- 优先，温和
       SELECT pg_terminate_backend(<pid>); -- 无效时再用

3. 检查锁等待：

       SELECT * FROM pg_locks WHERE NOT granted;

## 主从延迟

- 正常延迟：**小于 200ms**
- 告警阈值：延迟 **超过 5 秒**持续 1 分钟
- 延迟过大时，读流量会读到旧数据。涉及**资金与订单状态**的读操作必须强制走主库，不受此规则影响。

## 常见原因

| 现象 | 常见原因 |
|---|---|
| 从库延迟持续增长 | 大事务、DDL、从库单线程回放 |
| 主库连接数突增 | 连接泄漏、慢查询堆积 |
| 锁等待增多 | 长事务未提交、批量 UPDATE 范围过大 |

## 注意

`pg_terminate_backend` 会回滚事务，对资金类操作使用前必须与业务方确认。
