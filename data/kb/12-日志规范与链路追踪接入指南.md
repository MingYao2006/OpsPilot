# 日志规范与链路追踪接入指南

## 日志级别

| 级别 | 使用场景 | 生产是否开启 |
|---|---|---|
| ERROR | 需要人工介入的失败 | 是 |
| WARN | 可自愈但需关注的异常 | 是 |
| INFO | 关键状态流转 | 是 |
| DEBUG | 排查用细节 | 否，仅按需临时开启 |

禁止在循环内打 INFO 日志。单请求日志量超过 **50 条**视为违规。

## 必须携带的字段

- `trace_id`：全链路唯一，由入口网关生成，透传不重新生成
- `request_id`：单次请求唯一，用于同一请求内多服务关联
- `service` / `instance`：定位到具体实例
- `user_id`：脱敏后记录，禁止记录手机号与身份证原文

## 采样策略

- 错误链路：**100% 采样**，不允许丢弃
- 正常链路：1% 采样，高 QPS 接口可降到 0.1%
- 慢请求（超过 1 秒）：强制采样，不受采样率限制

## 日志脱敏

手机号保留前 3 后 4，银行卡保留后 4 位，密码与 token 一律不落盘。
脱敏必须在**写入前**完成，不允许先落盘再清洗。

## 常见误判

日志量突增**不等于**故障。先看是 ERROR 变多还是 DEBUG 被误开：
后者常见于发布时误带调试配置，回滚配置即可，不需要回滚代码。
