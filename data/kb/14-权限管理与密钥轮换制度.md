# 权限管理与密钥轮换制度

## 权限模型

采用 RBAC：用户 → 角色 → 权限。禁止给个人直接授权限。
- 生产环境写权限仅授予 **on-call 角色**，且需二次审批
- 只读权限可自助申请，审批时效 4 小时
- 离职账号在 **1 小时内**回收，由 HR 系统触发

## 最小权限原则

默认拒绝，按需申请。申请必须写明**用途与有效期**，
有效期最长 90 天，到期自动回收，续期需重新审批。

## 密钥轮换

| 密钥类型 | 轮换周期 | 是否可自动 |
|---|---|---|
| 数据库密码 | 90 天 | 是 |
| API Key | 180 天 | 是 |
| JWT 签名密钥 | 365 天 | 否，需双密钥灰度 |
| 根证书 | 3 年 | 否 |

JWT 密钥轮换必须支持**双密钥并行验签**，否则轮换瞬间全量用户掉线。
旧密钥在轮换后保留 **7 天**再下线，覆盖最长 token 有效期。

## 审计

所有生产环境写操作留存审计日志 **180 天**。
审计日志本身只可追加，不可修改或删除。

## 常见误判

收到密钥泄露告警**不要**直接删除密钥。直接删除会导致服务不可用，
正确顺序是：先签发新密钥 → 灰度切换 → 确认流量走新密钥 → 再吊销旧密钥。
