# 链路追踪与APM接入

## 接入要求

所有 Java 服务通过 Java Agent 接入，禁止业务代码硬编码 SDK 上报逻辑。
Agent 版本统一由基础平台下发，各服务不得自行升级。
接入后必须上报的三类数据：调用链、JVM 指标、慢 SQL。

新增服务接入前需在基础平台登记服务名、负责人与所属业务域，未登记的服务不上报数据。
Agent 启动参数由发布平台注入，禁止在启动脚本中重复指定，重复注入会导致 Span 重复上报。
接入完成的标准是：能在链路查询页面按 trace_id 查到完整链路，且 Span 数量与调用层数一致。

原始链路保留 7 天，聚合指标保留 90 天，错误链路额外归档 180 天。
上报量月环比增长超过 30% 需评估成本，优先降低正常链路采样率，而不是减少埋点。
单服务上报 QPS 超过 5000 时启用本地聚合，聚合窗口 10 秒，避免上报通道成为瓶颈。

## 采样策略

| 链路类型 | 采样率 | 是否可调 | 说明 |
|---|---|---|---|
| 错误链路 | 100% | 否 | 不允许丢弃 |
| 慢请求（>1s） | 100% | 否 | 强制采样 |
| 正常链路 | 1% | 是 | 高 QPS 服务可降至 0.1% |
| 健康检查与探针 | 0% | 否 | 完全不上报 |

采样决策在链路入口一次性决定，整条链路保持一致，禁止各服务独立采样，
否则会出现"父 Span 有、子 Span 无"的断链。
采样率变更走配置中心，生效延迟不超过 30 秒，变更后需观察 10 分钟确认上报量符合预期。

## 埋点规范

- Span 名称格式为 `服务名.方法名`，禁止使用含变量的动态名称，否则会打爆指标基数。
- 单条链路 Span 数量上限 200 个，超过部分截断并打 `truncated=true` 标记。
- 自定义标签每个 Span 不超过 10 个，标签值长度不超过 128 字符。
- 禁止把用户 ID、订单号等高基数字段写入 Span 名称，只能作为标签。

跨线程与异步调用必须显式传递上下文，线程池场景使用包装后的执行器，
否则异步分支会丢失父 Span，表现为链路在某个节点突然断裂。
消息队列场景在消息头中透传 trace_id，消费端沿用上游 trace_id 而不是新生成。

## 指标口径

APM 的应用响应时间以**入口 Span 耗时**为准，包含网关转发与网络耗时；
服务自身耗时以内部 Span 为准。两者差值超过 200ms 时优先排查网络与网关。
P99 与平均值的偏差超过 5 倍时，说明存在长尾，需按接口维度下钻。
错误率统计以入口 Span 的状态码为准，内部被捕获并降级处理的异常不计入错误率，
但必须在日志中保留，避免降级掩盖真实故障。

## 常见误判

APM 显示某接口耗时飙升，**不等于**该接口自身有性能问题。
先看链路瀑布图里的自身耗时占比：若自身耗时占比低于 20%，
瓶颈在某个下游依赖上，优化本服务代码不会有任何收益。
