# 网络分区与DNS故障处置

## 故障特征对照

| 现象 | 大概率原因 | 首要验证动作 |
|---|---|---|
| 同机房内调用正常，跨机房全失败 | 机房之间链路中断 | 两机房互 ping 与 MTR |
| 全站域名解析失败，IP 直连正常 | DNS 解析故障 | `dig @内网DNS 域名` |
| 部分实例失败、部分正常 | 单实例网络或网卡异常 | 对比失败实例所在宿主机 |
| 连接超时但 TCP 握手成功 | 中间设备丢包或 MTU 问题 | 抓包看是否有 ICMP 不可达 |

判定顺序固定为：先确认范围（单实例 / 单机房 / 全站），再确认层次（DNS / 网络 / 应用），
最后确认方向（单向 / 双向）。跳过前两步直接查应用日志，是排查耗时最长的一种路径。

## DNS 解析基线

- 内网域名 TTL 统一为 60 秒，禁止设置为 0 或超过 300 秒。
- 客户端 DNS 缓存上限 60 秒，与 TTL 对齐，避免摘除实例后仍被解析到。
- 每个服务至少配置 2 个内网 DNS 服务器，主备切换探测间隔 5 秒，连续 3 次失败即切换。
- DNS 解析失败重试 2 次，总耗时不超过 3 秒，禁止无限重试。
- 核心调用链禁止依赖 DNS，必须使用服务注册中心地址或长连接，避免解析故障放大为业务故障。

DNS 服务器自身按 3 副本部署，任一副本故障时剩余副本承担全部查询，
单副本容量按全量查询的 60% 设计，保证 1 副本故障后仍有 20% 余量。
解析结果变更后需在 5 分钟内完成全网生效确认，未生效的节点单独排查本地缓存。

## 网络分区处置

1. 确认分区边界：按机房、机架、可用区逐层缩小范围，10 分钟内给出初步结论。
2. 开启降级：非核心功能（推荐、评论、积分）直接降级，保留支付与下单。
3. 分区内的服务禁止自动切换主库，避免脑裂导致双写。切换主库必须人工确认。
4. 若分区超过 5 分钟未恢复，按机房级故障预案执行流量切换，切换后观察 10 分钟。
5. 恢复后必须做数据核对：重点检查分区期间的订单、支付、通知三类数据是否完整。

分区期间的消息队列可能出现双写，恢复后按消息唯一键去重，去重窗口取分区时长加 30 分钟。
若分区期间产生过主库切换，必须做全量数据比对，比对范围覆盖切换前后各 1 小时的数据。

## 与熔断降级的配合

跨机房调用超时阈值设为同机房的 2 倍，即同机房 500ms、跨机房 1000ms。
连续失败 20 次或失败率超过 50% 触发熔断，熔断后 30 秒进入半开状态，放行 5 个探针请求。
半开状态下探针全部成功才恢复全量，任一条失败则重新熔断并延长熔断时长到 60 秒。

## 常见误判

域名解析失败时，第一反应是重启 DNS 服务或刷新本地缓存，这通常无效。
先判断故障范围：若只有某个服务解析失败，问题在该服务的 DNS 配置或 hosts 文件；
若全站失败，才需要检查 DNS 服务器本身。盲目重启会中断正在恢复的解析链路。
